# Project instructions

## Timestamped workflow summaries

When the user explicitly asks to create or update `summary.md`, do not overwrite an existing summary. Create a new Markdown file directly in `workflow/` using the local Europe/Vienna timestamp:

`summary_YYYYMMDD_HHMMSS.md`

Each summary should be short and self-contained. Record the latest findings, decisions made in the conversation, current methodological direction, important artifact paths, material caveats, and immediate next steps. Preserve all earlier timestamped summaries. Move obsolete non-timestamped summaries to `workflow/archive/` instead of deleting them.
